# Quant AI · Quick Card Bot Operating Messages
Owner direction captured 2026-10-27. This is a BUILD CONTRACT, not a claim that the production feed, profile service, browser automation, or ad settlement is live. Read alongside `docs/UNIVERSAL-QUICK-CARD-CONTRACT.md`.

## Message 00: ALL BUILDERS — Card freshness before card creation
> Never publish a card that will become a frozen advertisement for expired information. Every time-sensitive card must declare the authoritative official source URL, retrieval method, last_verified_at, content_expires_at, fallback action, and next check. A generated card must check the real source on refresh; no successful check means no "LIVE" or "UPCOMING" label. Hide expired items or show an honest "Source unavailable" state and original-site link. Preserve the card identity and controls while rotating its underlying event, product, media, promotion or headline.

Implement a server-side freshness record per card, not just cache busting the HTML. Source verification and deployment are independent receipts. Hide broken unfinished cards from public rotation.

## Message 01: YELLOW RESEARCHERS — Sports / live events
> On each eligible view, prefer what is NEXT to watch: an official upcoming game, start time in the viewer's local timezone, teams, league, broadcaster/streaming service where reliably verified, original schedule link, and a working "Watch / Schedule" action. During an active game, refresh the actual score/source and timestamp. After final, allow a concise recap to a viewer ONCE for that game, mark `recap_seen` by user+event, then rotate the same card to the next verified matchup or another timely team/league. Never re-present an already-seen final-game recap as breaking or upcoming. Do not invent rights, streams, results, schedule dates, availability or live statuses.

State machine: `scheduled -> live -> final_unseen -> archived`; `final_unseen` is per viewer and becomes `archived` for that viewer after one view. Final recaps may be opened deliberately from history, but should not repeat in auto-rotation. On delayed source fetch use last-known only with visible stale marker and timestamp, or suppress when too old. Store schedule and actual start-time as timezone-aware instants; daylight-saving changes must not shift game times. Each new event gets a distinct event ID; reusing the same card ID must not erase historical event receipts.

## Message 02: GREEN BUILDERS — One search power button on EVERY card
> Place one compact accessible "⏻ Search" control in the existing bottom toolbar beside +1 Build, Share, Collect and Star. Do NOT scatter generic search inputs across cards or route all unnamed searches to Google. Activating the button should open one clearly labeled card-size result surface. Run the three owner-designated search routes for QuantaPhi, Infinity Phi and Omni Phi concurrently **only when each has a verified actual endpoint/adapter**. Show three independently attributed result groups in one surface, or three selectable tabs on narrow Android widths. A missing route is marked "Not connected", not silently filled with Google. Offer a source-open link per result and preserve the originating card and query context. Keep search on-card instead of detaching it to an unrelated page.

The query can be inferred from the active card's title and user intent, with one small editable input in the opened search surface when needed. Standalone search fields ONLY on cards where search is a primary original-provider feature (e.g. Library of Congress, Hotel Morrison collections, X/Twitter, Facebook, eBay/catalogs, documented databases); submit directly to that provider's authentic supported search or trusted browser adapter. Do not claim provider login, scraping or API access from an opened website. Respect CSP, provider permissions and Android popup behavior. De-duplicate results, annotate source/time, graceful partial results, timeout each route, and do not display invented results.

Acceptance: one search control per ordinary card, independent three-way status and an obvious partial failure, large enough taps, overflow-safe 320px Moto G Pure, keyboard and screen-reader support, no empty search bars.

## Message 03: QUANT AI — Consent-bound personalization and card selection
> Query per-user AI Quant signals only through the authenticated wallet-scoped Cloudflare profile adapter, after explicit permission. Rank timely useful cards against declared preferences, previous follows/stars/collects, prior exposures, freshness, topical context and exploration diversity. For the owner's opt-in profile, tech, science, atomic research and relevant food can be positive signals; do not hardcode those interests into everyone's feeds. Other users may see gaming, banking, shopping or different categories. Never read another wallet's quants, fabricate a profile from absent data, sell raw preference signals to advertisers, or infer sensitive traits for ad targeting.

Default to non-personalized contextual recommendations if profile unavailable or user opts out. Explain "Why this card"; provide editable interests, hide/mute, history and data deletion controls. Separate personalized content selection from ad eligibility, and give a viewer obvious control over personalization. Keep recommendation exposure and commercial click signals distinct and minimize retention.

Ranking prototype: eligibility first (ready, rights, verified source, unexpired, safe); then useful-match, timely-relevance, unseen boost, diversity and engagement. Apply frequency caps and avoid re-serving the same item even when reusing the same card shell. User click or collect must not cause an immediate fabricated preference or paid conversion.

## Message 04: ADPHI / SHOPPHI — Six flanking offers, auditable ledger
> After selecting the main card, derive optional adjacent product/service categories (example: Morgan dollar -> coin supplies, grading, books, loupe, cases, other relevant coins). Solicit eligible advertiser creatives/products through registered channels or authorized affiliate catalogs, not a broadcast of a person's private interests to billions of independent workers. Rank up to SIX distinct relevant flanking ads for quality, documented image rights, stock/relevance, user preferences where authorized, safety and diversity. Label Sponsored and disclose affiliate links. A viewer can hide ads; preserve product primary focus.

A served impression, a click, a "Collect for later" action and a verified completed purchase are FOUR DISTINCT events. A publisher earns 1 Star Coin per eligible attributed completed purchase **only if the merchant/advertiser agreed to these terms and a settlement source confirms it**. In the example "six shown, two purchased", TWO eligible verified purchases can yield TWO Star Coins, not six impressions or unspecified clicks. Treat a Star Coin as the project's in-app accounting unit, not automatically fiat currency or guaranteed affiliate revenue. Reversals, refunds, attribution windows, duplicate clicks, self-referrals, fraud checks and advertiser acceptance must be handled before final settlement. Use idempotent order/receipt keys; NEVER infer purchases merely because a browser clicked through to checkout.

## Message 05: BROWSER / CONNECTOR ENGINEERS — Free-first, authorized fallback
> For each Quick Card capability, evaluate (1) legitimate free documented API; (2) authorized website deep link/search; (3) own Cloudflare/Termux browser automation for public pages or user-explicit, permitted signed-in workflows; (4) a paid API only if specifically approved. Never require every public end user to bring an API key. Developer keys stay in private secrets, never JavaScript or public GitHub. Cloud browser and API may differ in fidelity, permission, stability and operational cost: test and disclose. Do not clone proprietary scripts, bypass paywalls/anti-bot mechanisms, read cross-origin credentials or impersonate a provider.

Browser route receipts include requested action, verified source URL, permission/consent context, checked_at, errors, observed output, and a bounded nonsecret result. Payments, public posts, account creation and other external writes require user review and confirmation.

## Message 06: LEE / INTEGRA / RELEASE — No pretend completion
Lee: own Cloudflare service binding, D1/KV storage, authentication, token handling, deployment and readback; report missing scopes precisely. Green: source code and tests; Yellow: independent current-site research; Quant AI: ranking decision; Integra: validation only. Before calling anything DONE prove actual original-site read, backend results, 320/360/393px Android rendering, correct logged-in/out behavior, per-viewer recap suppression, one-power-search action, consent isolation, and ad ledger idempotency. A GitHub PR, passing unit tests or a console screenshot by itself is not proof of a live production deployment.
